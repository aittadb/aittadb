# AittaDB Implementation Plan

- [ ] **TASK-182: Add the durable event repository primitive (promotes ROADMAP-009).** DoD: define one immutable namespace-owned event contract and narrow repository interface; add a forward D1 migration and schema manifest entry for opaque public UUIDs, internal ordered sequence, event type, bounded JSON payload, hashed optional idempotency key, request fingerprint, creation/expiry times, exact user/client ownership, uniqueness, supporting indexes, foreign keys, and inactive-subject write denial; implement D1 and memory append/get/list behavior with atomic exact-replay versus conflicting-reuse results; test deterministic ordering, immutability, duplicate and conflict behavior, malformed repository input, cross-user/client isolation, migration consistency, and memory/D1 parity; document the internal contract and failure semantics without exposing an HTTP route or claiming Events are available; and pass formatting, linting, type checking, focused tests, migration validation, and build.
- [ ] **TASK-183: Add feature-gated event configuration and authorization scopes (promotes ROADMAP-015).** DoD: add `FEATURE_EVENTS_ENABLED` with a fail-closed default of false plus finite payload, retention, cursor, page, quota, and read/publish/subscribe rate settings; define `events.publish`, `events.read`, and `events.subscribe` as AittaDB-only scopes; allow interactive clients and non-human service clients to receive only applicable configured scopes while preserving the prohibition on service identity claims, redirects, origins, ID tokens, and refresh tokens; update the reserved browser client and checked-in migration state consistently; omit event routes, controls, and scopes from runtime discovery/administration when disabled and reject disabled behavior before bodies, token consumption, rate limits, or repositories; test malformed configuration, scope escalation, service-client restrictions, feature visibility, and existing-scope compatibility; update `.env.example`, OpenAPI scope metadata, architecture, deployment guidance, and `AGENTS.md`; and pass full focused validation.
- [ ] **TASK-184: Enforce atomic event admission quotas.** DoD: extend event append with finite deployment, local-user, and user/client namespace item and byte ceilings using one affected-row-gated D1 admission mutation whose memory implementation has identical results; define exact UTF-8 payload accounting, distinguish quota exhaustion from idempotent replay and idempotency conflict, prevent retries from consuming quota twice, reject inactive principals, and leave reads/cleanup available when publication is denied; test each ceiling, concurrent boundary attempts, byte accounting, replay, cross-namespace independence, and repository failure paths; document configuration and operational recovery without revealing other namespaces or provider capacity; and pass formatting, linting, type checking, focused tests, migration checks, and build.
- [ ] **TASK-185: Add opaque expiring event cursors (promotes ROADMAP-013).** DoD: define a versioned AES-GCM cursor carrying only the last internal event sequence and bounded expiry, derived from existing private signing-key material and authenticated to the Events resource, exact principal, and client; reject malformed, noncanonical, tampered, expired, cross-user, cross-client, cross-resource, and key-rotation-invalidated cursors without exposing cursor contents or secrets; preserve a safe empty-stream checkpoint and deterministic resume position; add focused confidentiality and failure tests plus architecture/protocol documentation; and pass formatting, linting, type checking, focused tests, and build.
- [ ] **TASK-186: Add bounded event-retention cleanup (promotes ROADMAP-014).** DoD: delete only expired events in a configurable oldest-first bounded batch using supporting indexes and verified affected-row counts; add the category to D1/memory cleanup reports and redacted optional telemetry without logging event identity, type, payload, owner, client, or cursor; prove repeated cleanup is safe, unexpired events survive, namespace isolation is unchanged, limits are obeyed, failures are reported generically, and ordinary requests can schedule the work without a long background job; update retention/configuration/operations documentation and tests; and pass formatting, linting, type checking, focused tests, migration validation, and build.
- [ ] **TASK-187: Purge events during self-service account deletion.** DoD: add a bounded resumable event-purge phase before account finalization, update D1 completion guards and memory parity so no owned event can survive a completed deletion, keep service principals and unrelated users/clients untouched, reject new event writes after deletion begins, and preserve retry/lease semantics; test partial batches, retries, finalization blocking, cross-subject isolation, later same-email empty identity, and failure recovery; update account-deletion, privacy, threat-model, migration, and architecture documentation; and pass formatting, linting, type checking, focused tests, migration validation, and build.
- [ ] **TASK-188: Add scoped event publication at `POST /events` (promotes ROADMAP-010).** DoD: implement one feature-gated canonical operation for bearer and CSRF-protected current-session HTML clients, requiring `events.publish`; accept a bounded JSON object with a validated vendor-neutral event type and JSON data plus an optional bounded `Idempotency-Key` header (and equivalent protected HTML field), create a cryptographically random UUID event, return `201 Location` on creation, return the same event without another write on exact replay, and return deterministic `409` on key reuse with different content; enforce origin/CORS, body-before-repository limits, subject/client isolation, rate and quota controls, no implicit fan-out, no credential/payload logging, and no tokens in URLs or HTML; provide equivalent hypermedia/HTML controls, OpenAPI, examples, security docs, and positive/negative integration tests; and pass full validation and production build.
- [ ] **TASK-189: Add bounded event collection retrieval at `GET /events` (collection part of ROADMAP-011).** DoD: require `events.read`, return events oldest-first in a finite configured page, support the opaque continuation cursor and one exact bounded event-type filter, return a resumable next cursor and useful empty state, and expose equivalent HTML lists/navigation and hypermedia links/actions without raw JSON dumps; reject invalid/expired cursors, disabled features, missing scope, disabled clients, inactive subjects, foreign origins, and cross-user/client access before disclosure; keep immediate polling as the default behavior and use `Cache-Control: no-store`; update root/session operation maps, OpenAPI, examples, threat model, and route-parity tests; and pass full validation and production build.
- [ ] **TASK-190: Add immutable event item retrieval at `GET /events/{id}` (item part of ROADMAP-011).** DoD: require `events.read`, validate one canonical UUID identifier, return only the exact caller-owned immutable event as hypermedia JSON or accessible HTML, link back to its collection, advertise no update/delete operation, and return one generic not-found result for malformed, absent, other-user, and other-client identifiers; enforce feature, token, CORS, inactive-subject, cache, and request-bound controls before repository disclosure; update OpenAPI, examples, architecture, and positive/negative parity tests; and pass full validation and production build.
- [ ] **TASK-191: Add bounded long-poll event delivery at `GET /events?wait=...` (promotes ROADMAP-012).** DoD: extend the collection operation so an explicit bounded wait requires both `events.read` and `events.subscribe`, requires a valid resume cursor, waits no longer than the configured Worker-safe maximum, stops on request cancellation, returns promptly when a later event exists, and returns a documented empty timeout response while ordinary polling remains unchanged; perform only a finite configured number of repository reads, enforce a separate subscribe rate limit before waiting, use no process-memory correctness or background worker, and preserve cursor/namespace/feature/CORS/deletion boundaries; add deterministic clock/scheduler tests for success, timeout, cancellation, invalid cursor, disabled client, scope failures, rate limits, and cross-namespace publication; update OpenAPI, HTML/hypermedia controls, examples, performance/threat documentation, README capability claims, and `AGENTS.md`; and pass complete validation and production build.
- [ ] **TASK-192: Deploy the exact Events candidate to `test.aittadb.com`.** DoD: push one completely validated feature-branch commit to the sole draft PR, package that exact source and checked-in migrations, save and deploy it only to the preapproved acceptance Site, enable Events there with finite test limits, and prove deployment success plus D1/R2 health while byte-for-byte preserving unrelated environment entries, secrets, feature flags, bindings, access policy, and custom domains; record only non-sensitive commit/version/configuration evidence and confirm `aittadb.com` source, environment revision, data, access, DNS, and domains were untouched.
- [ ] **TASK-193: Prove hosted event publication and idempotency.** DoD: on the exact TASK-192 acceptance deployment, use one temporary signed-in or service namespace to prove first publication, exact idempotent replay without another row, conflicting key reuse rejection, payload/type/body limits, and disabled publication behavior; record statuses and opaque counts only, with no identity, client secret, token, key, payload, event identifier, or environment value; remove every event fixture created by this proof through bounded retention or isolated acceptance cleanup; and leave unrelated deployment state unchanged.
- [ ] **TASK-194: Prove hosted event retrieval and cursor resume.** DoD: on the exact TASK-192 deployment, publish bounded synthetic fixtures in one temporary namespace and prove deterministic collection ordering, finite pagination, opaque cursor resume without duplicates, exact type filtering, immutable item retrieval, malformed/expired cursor rejection, and generic missing/foreign item behavior; record only coarse evidence, remove all fixtures, and leave unrelated deployment state unchanged.
- [ ] **TASK-195: Prove hosted bounded long polling.** DoD: on the exact TASK-192 deployment, prove one valid cursor waits and returns promptly after a later same-namespace publication, one wait reaches its documented empty timeout bound, ordinary polling remains immediate, and invalid cursor, missing subscribe scope, rate-limit, cancellation where observable, and foreign-namespace publication do not disclose or unblock data; record only timings/statuses within coarse safe ranges, remove all fixtures, and leave unrelated deployment state unchanged.
- [ ] **TASK-196: Prove hosted Events authorization and namespace isolation.** DoD: on the exact TASK-192 deployment, use two temporary clients and two existing authorized test identities to prove publish/read/subscribe scope separation, current-session behavior, service-token non-human claims, disabled-client denial, anonymous denial, cross-client isolation, and cross-user isolation; never record identity, local subject, secret, token, event ID, payload, or complete credential-bearing request; disable and remove grants for temporary clients, remove fixtures, and leave unrelated deployment state unchanged.
- [ ] **TASK-197: Prove hosted event quotas, retention, and deletion safety.** DoD: on the exact TASK-192 deployment with bounded temporary settings, prove one namespace item or byte ceiling rejects the boundary-crossing append without harming reads, expired events are removed only by bounded cleanup while unexpired/foreign events survive, and an account-deletion boundary blocks new event writes and cannot finalize while owned event residue remains; use only disposable fixtures suitable for deletion, record coarse counts/statuses, restore any altered temporary limit immediately after the proof, and leave unrelated deployment state unchanged.
- [ ] **TASK-198: Restore the Events acceptance deployment after proofs.** DoD: verify all temporary events, clients, grants, deletion fixtures, credentials, and local artifacts from TASK-192 through TASK-197 are removed or irreversibly disabled; restore every temporary acceptance environment setting while retaining only the explicitly intended Events feature state, redeploy the same reviewed source if configuration application requires it, confirm health and public/private authorization baselines, and prove `aittadb.com` remained untouched; archive each completed PLAN description unchanged with its evidence in `CHANGELOG.md`, leave `PLAN.md` with zero unchecked items, run complete validation, push the final feature branch, and leave the single PR ready for user review without merging it.
